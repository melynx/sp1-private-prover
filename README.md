# sp1-private-prover

`sp1-private-prover` is a private, SP1 6.2.2 prover-network compatible service. It accepts the network requests made by an unchanged SP1 6.2.2 client and proves locally with the pinned `melynx/sp1` ROCm port. It never reads a chain RPC endpoint and never sends a chain transaction.

The implemented gRPC methods are `CreateArtifact`, `GetProgram`, `CreateProgram`, `GetProofRequestParams`, `GetNonce`, `GetProversByUptime`, `RequestProof`, `GetProofRequestStatus`, and `CancelRequest`. Artifact upload, proof download, liveness, readiness, and Prometheus metrics use the auxiliary HTTP listener.

## Trust and compatibility

The service verifies each EIP-191 signature and recovers its Ethereum address. `access_mode = "allowlist"` denies every signer when `signer_addresses` is empty. `access_mode = "denylist"` accepts every valid signer when `signer_addresses` is empty. Add the public address for the existing `prover_credential`; the private key and the credential value remain outside this service.

Program registration derives the SP1 verifying key from the uploaded ELF. It rejects any mismatched ELF, verifying key, or verifying key hash. Proof input is the zstd-compressed bincode `SP1Stdin` generated by SP1 6.2.2. The first release rejects `SP1Stdin.proofs` when it is not empty. Proof downloads contain raw bincode `ProofFromNetwork` with circuit version `v6.1.0`.

The transaction hash returned by `CreateProgram`, `RequestProof`, and `CancelRequest` is a deterministic local compatibility receipt. It is not a chain transaction.

## Build

Initialize the pinned submodule:

```sh
git submodule update --init --recursive
test "$(git -C vendor/sp1 rev-parse HEAD)" = f782d4ed34e5876589ae53538bd4ad68e416f031
```

Build `vendor/sp1/target/release/sp1-rocm-server` with ROCm 7.14 for `gfx1151`. Its required SHA-256 is `942ce14d2d7474ca58c081b0b46b404df1cff76398bb1c5077e6764af7acde72`. Then run:

```sh
SP1_ROCM_ALLOCATOR=async scripts/prepare-dist.sh
podman build -t localhost/sp1-private-prover:local -f Containerfile .
```

`scripts/prepare-dist.sh` copies the exact local ROCm installation into the image. The final service never installs or downloads a binary or circuit at runtime. Do not set `SP1_ROCM_ALLOCATOR=arena`; the service rejects that setting.

## Circuit restore

Restore the previously verified `v6.1.0` archives into a new directory:

```sh
scripts/restore-circuits.sh <archive-directory> <new-circuit-directory>
```

The script checks archive hashes, restores `plonk/v6.1.0` and `groth16/v6.1.0` into a new staging directory, checks every extracted file, writes a combined `SHA256SUMS.extracted`, and then renames the directory. The service repeats every extracted-file hash and the ROCm server hash before it becomes ready.

## Rootless Podman 6 and `crun`

The installer resolves the render node from PCI device `0000:c5:00.0`. It does not depend on `card0` numbering.

```sh
mkdir -p "$HOME/.config/containers/systemd"
install -m 0644 deploy/sp1-private-prover.network "$HOME/.config/containers/systemd/sp1-private-prover.network"
scripts/install-quadlet.sh <state-directory> <circuit-directory> <config-file> "$HOME/.config/containers/systemd/sp1-private-prover.container"
systemctl --user daemon-reload
systemctl --user start sp1-private-prover.service
```

The Quadlet `[Install]` section adds the generated service to `default.target` for boot startup. Podman 6 does not allow `systemctl --user enable` on the generated service.

The generated Quadlet passes `/dev/kfd`, the render node resolved from PCI device `0000:c5:00.0`, and any other AMD render nodes that ROCm 7.14 needs while it creates its device list. `HIP_VISIBLE_DEVICES=0` then selects only `gfx1151` for proving. The generated Quadlet uses `GroupAdd=keep-groups` and `UserNS=keep-id`. It gives `/dev/shm` 32 GiB because the SP1 native executor stores its guest memory and trace ring there; Podman's 64 MiB default causes the executor to exit with `SIGBUS`. The Podman internal network blocks container Internet egress while published host ports remain reachable. The container publishes gRPC port `50051` and auxiliary HTTP port `50052`.

Plain HTTP is appropriate only on loopback, a private LAN, or an authenticated VPN. Configure `tls_cert` and `tls_key` to enable TLS on both the gRPC and auxiliary HTTP listeners.

## Client configuration

Keep `backend = "sp1"` and `execution = "network"`. Change only the endpoint to the private service:

```toml
endpoint = "http://<private-prover-host>:50051"
```

The unchanged atakit daemon does not propagate portal cancellation to its SP1 network request. The private service can finish such a proof, but the daemon will not report it as successful.

## Storage and limits

SQLite stores signer nonces, program registrations, artifact records, deterministic request identifiers, and job state. Content-addressed files store expanded program and input artifacts. Proof bytes are written and synced through a temporary file before the job changes to `fulfilled`. A restart changes interrupted `running` jobs back to `queued`; program handles are recreated on first use.

The defaults permit one active GPU job, one active and four queued jobs per signer, and 32 queued jobs globally. The defaults also enforce a 64 MiB ELF limit, 256 MiB compressed and 512 MiB expanded artifact limits, `10^12` cycles, `10^9` gas, a four-hour deadline, a 40 GiB `gfx1151` GTT guard, 15-minute unused upload expiry, and 24-hour terminal job retention.

If the GTT counter exceeds the configured guard, readiness fails and the service exits. Podman then terminates the ROCm child in the container and restarts the complete service. The service uses only caller-uploaded local artifact identifiers and never fetches a caller-supplied external URL.

## Validation

Run the local checks:

```sh
cargo fmt --all --check
cargo test
cargo clippy --all-targets -- -D warnings
git diff --check
```

GPU acceptance also requires all four Fibonacci proof modes, 100 sequential compressed requests, 25 groups of four concurrent clients, an unchanged `atakit-proverd-sp1` saved SEV-SNP evidence run, independent proof verification, blocked runtime Internet egress, idle-memory confirmation after shutdown, and the latency bound stated in the project acceptance plan.
